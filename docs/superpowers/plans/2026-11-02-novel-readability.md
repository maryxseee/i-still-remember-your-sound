# Readability and visual-novel flow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Виконати прямий запит користувачки: великий чіткий текст, плавне проходження через репліки й зрозумілі покрокові головоломки, як у візуальній новелі.
**Architecture:** Зберегти перевірену сюжетну модель; окремий модуль GameFlow визначає короткі репліки для поточного стану. Необов’язкове presentation у збереженні тримає позицію репліки та режим огляду/завдання. Новий CSS після базового прибирає дрібні шрифти, слабкий контраст і вузьку бічну колонку.
**Tech Stack:** Наявні HTML/CSS/JavaScript і Node test runner, без нових залежностей.
**Spec:** Пряме повідомлення користувачки від 02.11.2026 та цей короткий опис; жодних змін зданого DOCX, сюжету, правил фіналів або музичних матеріалів.

## Design / approaches
Обрано за запитом: сцена + велике нижнє діалогове вікно, по одній репліці, «Далі», після вступу огляд і явна кнопка початку головоломки. Альтернатива лише збільшити нинішню бічну колонку усунула б дрібний текст, але не пояснила б послідовність взаємодії. Користувачка прямо просить зробити зміни; повторного дозволу не потрібно.

## Global Constraints
- Репліки 22 px на звичайному екрані, не менше 20 px на вузькому; основні кнопки не менше 17 px.
- Текст одразу повністю видимий, без розмиття, друкування по літерах і руху текстових шарів.
- Старі збереження й відкриті фінали залишаються сумісними.
- Клавіатура, Escape, текстове проходження без звуку, повтори після помилок.

## Review Focus
- «Далі» не має самостійно розв’язувати завдання або записувати сюжетний вибір.
- Після помилки — зрозуміла репліка й повернення до тієї самої спроби.
- Перезавантаження відновлює позицію діалогу, старі збереження отримують безпечну початкову позицію.
- Усі наступні репліки/дії досяжні на телефоні й з клавіатури.
- Два правильні CD-маршрути та всі фінали залишаються досяжними.
